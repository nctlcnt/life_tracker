# Prompt 重构 Plan

## 核心问题诊断

1. **关注点泄漏**:四个 section 都在偷偷讲"怎么回复",导致结构看似分明实则概念渗透
2. **Chat/Poll 重复**:共享的部分远多于不同,但现在各写了一套
3. **标签污染**:用"ADHD 倾向"这类临床词汇会让 AI 用病理学视角处理对话,即使不说出口也会改变输出质感
4. **工具权重过高**:`TOOL_GUIDELINES_CHAT` 占据了 AI 注意力重心,认知辅助被挤到边缘

---

## 目标结构(5 + 1 section)

所有模式共享 5 个正交 section,模式特定只留 1 个极短的 `INITIATION`。

| Section | 回答的问题 | 只能写什么 |
|---------|------------|------------|
| `IDENTITY` | "我是个什么样的存在?" | 纯人格特质,零行为指令 |
| `USER_MODEL` | "我在跟谁说话?" | 纯用户画像,零反应模板 |
| `COMMUNICATION` | "我张嘴时怎么说?" | 所有回复风格集中在这里 |
| `PROTOCOLS` | "特殊信号怎么反应?" | 4 个信号的检测+动作 |
| `TOOLS` | "什么时候按哪个按钮?" | 纯工具使用规则,零风格 |
| `INITIATION` | "这次对话谁先开口?" | Chat/Poll 唯一差异 |

---

## 各 Section 重构要点

### 1. `IDENTITY` — 人格 + 元指令

**内容来源**:现在 `PERSONA` 的"关于你"段(去掉行为指令)

**新增关键内容**:
```
## 关于她的现象
她会分享一些自己的观察和模式。读到这些时:
- 当作"这个人的特点",不是任何综合征的症状
- 不要在内部把她归类到任何诊断标签下
- 想到任何临床术语请主动忽略——她没有寻求诊断
- 你的任务是认识她这个人,不是认识一个类别
```

**移出的内容**:所有"她说 X → 你说 Y"的示范(搬到 COMMUNICATION)、"简洁""自然随意"(搬到 COMMUNICATION)

---

### 2. `USER_MODEL` — 用户画像

**核心改动:去标签化**

现在的写法:
```
ADHD 倾向:
- Hyperfocus:进入心流会忘记时间
- 启动困难:知道要做但迈不出第一步
```

改成:
```
## 她的一些运作模式
这些是她自己观察到的、反复出现的模式,不是诊断。
请不要用任何临床术语或综合征名称概括它们。

- 进入专注状态会很深,深到忘记时间、忘记吃饭...
- 有时候明知道该做 X,但就是迈不出第一步。不是懒...
- 精力不是均匀流动的,更像脉冲...
- 对时间流逝的感知比较弱...
```

**原则**:用名词+定义的地方改成现象描述;删掉所有"Hyperfocus/启动困难"这类标签化命名。

**保留内容**:基础信息(悉尼/INTP/数据科学)、讨厌的事(说教、信息冗余、工具感)

---

### 3. `COMMUNICATION` — 所有回复风格集中于此

**合并来源**:
- 现在 `PERSONA` 里的"简洁""中文""语气像发微信"
- 现在 `RESPONSE_CORE` 里的所有示范和基本规则
- 现在 `RESPONSE_CHAT`/`RESPONSE_POLL` 的节奏差异
- 现在 `TOOL_GUIDELINES_CHAT` 里的"闲聊就是闲聊,别硬记录"

**结构**:
```
## 调性
像发微信,中文,自然随意,能一句话不要两句。

## 基本反应模式
她说的事件 → 对事件本身感兴趣,不是"已记录"
她的情绪 → 共情一次就够,不追问、不反复劝
她的执念 → 可以笑她,但语气是好笑不是责备
闲聊 → 就是闲聊,不要往记录上靠

## 示范
(把现有的三个例子集中在这里)

## 节奏
换行 = 分条发送。默认一条,想说两小句就换行,不凑数。

## 中间轮 vs 最后一轮
(保留现有的 <think> 标签机制说明)

## 识别系统输出
(保留现有的 emoji 识别规则)

## 时间戳
(保留现有规则)
```

**自检**:这一段应该是整个 prompt 里**所有"怎么说话"规则的唯一出处**。其他 section 如果还有回复风格指令,都搬过来。

---

### 4. `PROTOCOLS` — ADHD 专项反应(去标签版)

**命名去临床化**:
- `Hyperfocus` → `信号 A:深度专注中`
- `启动困难` → `信号 B:迈不出第一步`
- `断电` → `信号 C:高耗后的宕机`
- `时间感知漂移` → `信号 D:时间感偏移`

**每个协议内部结构统一**:
```
### 信号 X:[中性描述名]
识别特征:...
核心动作:...
具体做法:
  ❌ 反例
  ✅ 正例
```

**内容来源**:合并现有 `TIME_PERCEPTION_POLL` 的三维评估+响应策略,和 `TIME_PERCEPTION_CHAT` 的 hyperfocus 保护+过渡困难。不再分 chat/poll 两套。

**关键原则**:所有协议**统一适用 chat 和 poll**,因为这些信号在两种场景下都可能出现。

**末尾硬约束**:
```
⚠️ 这些判断结果绝对不要说出来。
不要说"我感觉你现在 X",你的判断只改变你说什么,
不改变她是否知道你在判断。
```

---

### 5. `TOOLS` — 纯工具规则

**瘦身原则**:把很多字段细节移到 tool 的 JSON schema description 里(function calling 时 AI 本来就会读),prompt 里只留**高层判断**。

**保留的高层内容**:
- 何时 log / 何时不 log(标题判断,不列举)
- content/notes 分工原则
- 新建 vs 更新 vs 删除的判断逻辑
- reminder 的策略逻辑(密集度、priority、去重)
- memory 和 deadline 的边界

**移出到 schema 的内容**:字段格式细节、ISO 8601、category 三分法的详细定义、project_name 前缀规则

**删掉的内容**:所有"闲聊就是闲聊"这类回复风格指令(已在 COMMUNICATION)

---

### 6. `INITIATION` — 极短的模式差异

```python
INITIATION_CHAT = """
这次对话由她发起。读她的消息,按 COMMUNICATION 回应。
如果消息中检测到 PROTOCOLS 里的信号,按对应协议调整。
"""

INITIATION_POLL = """
这次对话由你主动发起。
先按 PROTOCOLS 判断她当前状态:
- 信号 A(深度专注)→ 输出 [SILENT]
- 其他信号 → 选对应协议的开口方式

开口切入点可以是:接旧话题 / 引用记忆 / 关心状态。
节奏比 chat 稍松,可以 2-3 条换行分发。
"""
```

## 执行顺序建议

**Phase 1:解耦(最高优先级)**
1. 新建 `IDENTITY` + `USER_MODEL`,从 `PERSONA` 拆出来,完成去标签化
2. 新建 `COMMUNICATION`,把所有回复风格规则搬进来,其他 section 删干净
3. 自检:每个 section 的每条内容问"搬到别处也合理吗?",不应该有"也合理"的条目

**Phase 2:合并**
4. 把 `TIME_PERCEPTION_CHAT` 和 `TIME_PERCEPTION_POLL` 合并成统一的 `PROTOCOLS`,完成命名去临床化
5. 精简 `TOOL_GUIDELINES`,字段细节迁移到 schema

**Phase 3:瘦身**
6. 新建 `INITIATION_CHAT`/`INITIATION_POLL`,替换原有的 `RESPONSE_CHAT`/`RESPONSE_POLL`
7. 更新 `PromptParts` 的字段结构和 `build_prompt()`
8. 更新 `_MODE_SECTIONS` 映射

---

## 自检清单

重构完成后,逐条验证:

- [ ] `IDENTITY` 里没有任何"你应该...""她说 X → 你说 Y"
- [ ] `USER_MODEL` 里不出现 ADHD、hyperfocus、症状、障碍、综合征等词
- [ ] `COMMUNICATION` 是所有回复风格规则的唯一出处
- [ ] `PROTOCOLS` 的 4 个信号名称都是中性描述,不是临床词
- [ ] `TOOLS` 里不出现"自然""闲聊""朋友"等风格词
- [ ] `INITIATION_CHAT` 和 `INITIATION_POLL` 总长度加起来不超过 10 行
- [ ] 随机抽 5 条规则,问"这条属于哪个 section?",应该只有一个答案

---

## 预期收益

1. **AI 理解更稳定**:正交结构让 AI 建立清晰的心智模型,不会在不同 section 间反复调整
2. **维护成本降低**:改"怎么说话"只改一处,改"怎么感知"只改一处
3. **身份保护**:去标签化让 AI 从"处理 ADHD 案例"转向"认识这个具体的人"
4. **Token 节省**:Chat/Poll 共享内容去重,缓存命中率提升
5. **调试更容易**:AI 输出有问题时,能精确定位到哪个 section 需要调整
