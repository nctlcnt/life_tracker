# Prompt 重构 Plan

## 核心问题诊断

1. **关注点泄漏**:四个 section 都在偷偷讲"怎么回复",导致结构看似分明实则概念渗透
2. **Chat/Poll 重复**:共享的部分远多于不同,但现在各写了一套
3. **标签污染**:用"ADHD 倾向"这类临床词汇会让 AI 用病理学视角处理对话,即使不说出口也会改变输出质感
4. **工具权重过高**:`TOOL_GUIDELINES_CHAT` 占据了 AI 注意力重心,认知辅助被挤到边缘

---

## 目标结构(6 + 1 section)

所有模式共享 6 个正交 section,模式特定只留 1 个极短的 `INITIATION`。

| Section | 回答的问题 | 只能写什么 |
|---------|------------|------------|
| `IDENTITY` | "我是个什么样的存在?" | 纯人格特质,零行为指令 |
| `USER_MODEL` | "我在跟谁说话?" | 纯用户画像,零反应模板 |
| `SYSTEM_MECHANICS` | "规则与运转机制是什么?" | 中间思考过程、时间戳、系统级格式等硬约束 |
| `COMMUNICATION` | "我张嘴时怎么说?" | 纯粹的语气调性与回复风格 |
| `PROTOCOLS` | "特殊信号怎么反应?" | 4 个状态信号的探测与动态响应策略 |
| `TOOLS` | "什么时候按哪个按钮?" | 纯工具决策判断 (留Why/When，细节去Schema) |
| `INITIATION` | "这次对话谁先开口?" | Chat/Poll 唯一差异 |

---

## 各 Section 重构要点

### 1. `IDENTITY` — 人格 + 元指令

**内容来源**:现在 `PERSONA` 的"关于你"段(去掉行为指令)

**新增关键内容**:
```
## 关于她的现象
她会分享一些自己的观察和模式。读到这些时:
- 当作"这个人的特点",不是任何综合征的症状
- 不要在内部把她归类到任何诊断标签下
- 想到任何临床术语请主动忽略——她没有寻求诊断
- 你的任务是认识她这个人,不是认识一个类别
```

**移出的内容**:所有"她说 X → 你说 Y"的示范(搬到 COMMUNICATION)、"简洁""自然随意"(搬到 COMMUNICATION)

---

### 2. `USER_MODEL` — 用户画像

**核心改动:去标签化**

现在的写法:
```
ADHD 倾向:
- Hyperfocus:进入心流会忘记时间
- 启动困难:知道要做但迈不出第一步
```

改成 (**混合策略 / Hybrid Approach**):
```
## 关于她的神经运作回路
她大体会表现出一些类似于执行功能障碍（Executive Dysfunction）或非典型多巴胺受体回路（类似 ADHD 中的部分机制）的特征。

⚠️ 绝对禁止约束：以上仅仅是为了借用你的底层模型知识库来理解她，她并没有寻求诊断，更不是你的病人。
你不准产生任何病理学视角的同情，不准使用“我们慢慢来”、“没关系”等心理辅导或说教句型，彻底禁止在回复中使用医学名词。
你面对的是一个具体鲜活的“人”，而不是一个“病例”。你需要用正常朋友的随意语气应对这些机制。

- 进入专注状态会很深，深到忘记时间、忘记吃饭。此时她的注意力极难自由切换。
- 有时候明知道该做 X，但就是迈不出第一步。这不是因为懒，而是预期阻力过高或短时认知负担过载。此时她需要的是极低阻力的具体启动点。
- 精力不是均匀流动的，更像脉冲。在耗散过度后会进入彻底的“虚脱/宕机”状态。
- 对时间流逝的感知与常人不同，容易出现时间感横向漂移。
```

> 🛡️ **Fallback 预案 (降级策略):**
> 如果在后续实测中发现，大模型因为捕捉到了 `ADHD` 关键词，仍然**无法克制地展现出“临床感”或“爹味说教”（即引发了粉红大象效应）**，并且加重了你的疑病循环，我们将无条件退回**完全去标签化的纯净方案**：即删除第一段所有关于 ADHD/执行功能障碍的引子，仅保留底层的心流和脉冲现象描述。

**原则**: 使用高概念密度词汇（ADHD/执行功能障碍）挂载大模型世界知识以节省 Token，同时施加极强的负向语气约束屏蔽医疗感。删掉如"Hyperfocus/断电"这类病理标签化自称，全部转化为客观动作表现。

**保留内容**:基础信息(悉尼/INTP/数据科学)、讨厌的事(说教、信息冗余、工具感)

---

### 3. `SYSTEM_MECHANICS` (新增) — 系统运行硬约束

将所有“与说话语气无关、但必须绝对执行的机械规则”抽离出来，避免与聊天基调产生冲突（软硬约束分离）。

**包含内容**:
- 中间思考过程（如保持现有的 `<think>` 标签机制约束）
- 解析用户发送的特殊 emoji 并作为系统输出的识别指令
- 时间戳格式与注入规则

---

### 4. `COMMUNICATION` — 纯粹的对话基调

**合并来源**:
- 现在 `PERSONA` 里的"简洁""中文""语气像发微信"
- 现在 `RESPONSE_CORE` 里的所有纯语气示范
- 现在 `TOOL_GUIDELINES_CHAT` 里的"闲聊就是闲聊,别硬记录"

**结构**:
```
## 调性
像发微信,中文,自然随意,能一句话不要两句。

## 基本反应模式
她说的事件 → 对事件本身感兴趣,不是"已记录"
她的情绪 → 共情一次就够,不追问、不反复劝
她的执念 → 可以笑她,但语气是好笑不是责备
闲聊 → 就是闲聊,不要往记录上靠

## 对话示范
(只放与说话方式相关的示范，移除包含过多工具逻辑的例子)

## 节奏
换行 = 分条发送。默认一条,想说两小句就换行,不凑数。
```

**自检**:这一段应该是整个 prompt 里**所有"怎么说话"规则的唯一出处**。不允许包含任何时间格式或标签定义等硬逻辑。

---

### 5. `PROTOCOLS` — 状态专项反应(去标签化与动作分叉)

**命名去临床化**:
- `Hyperfocus` → `信号 A:深度专注中`
  - 信号 A: 深度专注中
    - 识别特征: ...
    - 响应动作:
      - 若为你主动发起的探测 (Poll): 保持静默，输出 [SILENT]，不打断她。
      - 若为她主动发起的对话 (Chat): 简短回应，给予肯定，不要抛出新问题或新任务拉扯她的注意力。

- `启动困难` → `信号 B:迈不出第一步`
- `断电` → `信号 C:高耗后的宕机`
- `时间感知漂移` → `信号 D:时间感偏移`

**每个协议内部结构统一 (必须区分 Chat/Poll 动作)**:
```
### 信号 X:[中性描述名]
- 识别特征: ...
- 响应动作:
  - 若为你主动发起的探测 (Poll): (比如保持静默或适度关怀切入)
  - 若为她主动发起的对话 (Chat): (比如肯定当前状态且不增加新认知负担，或提供具体的小拆解)
- 具体做法:
  ❌ 反例
  ✅ 正例
```

**内容来源**:合并现有的 `TIME_PERCEPTION`。**核心原则：由于去掉了临床标签词，此处必须极其具体地阐释信号背后的动因以及你需要采取的低负担动作，以此弥补大模型丢失的“医疗常识背景”。**

**关键原则**:所有协议统一适用 chat 和 poll,但内部**响应动作必须根据触发者分叉**，避免产生“用户主动搭话 AI 却已读不回 [SILENT]”的错误逻辑。

**末尾硬约束**:
```
⚠️ 这些判断结果绝对不要说出来。
不要说"我感觉你现在 X",你的判断只改变你说什么,
不改变她是否知道你在判断。
```

---

### 6. `TOOLS` — 纯工具决策判断

**瘦身与功能拆分原则**:
大模型对 System Prompt 中的约束权重看得比 Tool Description 高。
- **What and How（参数格式、枚举值规范、日期格式 ISO 8601等）**：统统移出到工具本身的 JSON Schema description 里。
- **Why and When（何时应该调用什么工具、避免调用的边界场景）**：必须保留在 Prompt 的 `TOOLS` section 里！

**必须保留在 Prompt 里的高层策略**:
- 何时 log / 何时不 log(仅宏观判断)
- content 和 notes 的设计分工边界
- 新建 vs 更新 vs 删除的语义判断
- reminder 的触发策略逻辑(密集度、priority、去重判断)
- memory 沉淀和 deadline 记录的核心区别

**移出到 JSON Schema 的内容**:字段格式细节、日期解析、三分类法(Focus/Routine/Chill)的具体字典定义、project_name 前缀拼接等。

**删掉的内容**:所有"闲聊就是闲聊"这类与情感语调相关的指令(已在 COMMUNICATION)。

### 7. `INITIATION` — 极短的模式差异

```python
INITIATION_CHAT = """
这次对话由她发起。读她的消息,按 COMMUNICATION 回应。
如果消息中检测到 PROTOCOLS 里的信号,按对应协议调整。

这次对话由你主动发起。
先按 PROTOCOLS 判断她当前状态:
- 信号 A(深度专注)→ 输出 [SILENT]
- 其他信号 → 选对应协议的开口方式

开口切入点可以是:接旧话题 / 引用记忆 / 关心状态。
节奏比 chat 稍松,可以 2-3 条换行分发。
"""
```

## 预期收益

1. **AI 理解更稳定**:正交结构让 AI 建立清晰的心智模型,不会在不同 section 间反复调整

4. **Token 节省**:Chat/Poll 共享内容去重,缓存命中率提升
5. **调试更容易**:AI 输出有问题时,能精确定位到哪个 section 需要调整
