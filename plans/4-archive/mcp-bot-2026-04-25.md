# MCP Bot B Phase 1 — 整体推翻（2026-04-25）

> 状态：**整体推翻**。代码已 git revert（commit `0631972`）。原始两个 feat commit (`465aefb` / `7933b63`) 仍在历史里供参考。
> 配套 devlog 同日条目记录了从过程中沉淀下来的可复用结论。

## 原方案一句话

新建独立 Discord application（Bot B），通过两个 stdio MCP server（obsidian + lifetracker）接 Obsidian vault 和 SQLite，做手机端只读查询入口；Bot A 不动。10 步全跑通，3 个真实 query 测试通过。

## 推翻理由

**技术上一切跑通**，但价值假设崩了：

### 1. MCP 协议层对单用户场景没有架构价值

Bot A 用 in-process function dispatch（`bot/tools.py` + `_execute_tool`），Bot B 走 stdio MCP——模型能调的工具集**完全一样**、计费方式**完全一样**、可靠性反而**更低**（多两个子进程 + IPC 失败点）。MCP 的设计目标是**让外部 LLM client（Claude Code、ChatGPT desktop、Cursor 等）能用你的工具**。单用户单 bot 用不上这个跨进程能力，新建一套 MCP 基础设施买到的全是 IPC 开销和复杂度，零新功能。

### 2. 想让计费走订阅而不是 API：所有路径被 TOS 堵死

| 路径 | 是否能走订阅 | 来源 |
|---|---|---|
| Claude Agent SDK + OAuth token | ❌ Anthropic 政策 2026-02 enforced 禁止；强制 `ANTHROPIC_API_KEY` | [agent-sdk-python issue #559](https://github.com/anthropics/claude-agent-sdk-python/issues/559) |
| `claude -p` headless 当 subprocess | ❌ 永远走 API，即使 `claude /login` 登的是订阅；有用户因此 2 天烧 $1800 | [Claude Code 官方 headless 文档](https://code.claude.com/docs/en/headless) + [issue #43333](https://github.com/anthropics/claude-code/issues/43333) |
| 手机 web claude.ai/code + 本机 stdio MCP | ❌ 物理隔离，云端 VM 够不到本机进程 | (架构推断 + subagent 核实) |
| 手机 web + 远端 HTTP MCP（自建公网） | ⚠️ web 端是否支持用户自定义 remote MCP，**官方文档无明确说明**，需实测 + 自己暴露公网 + 鉴权 | (官方文档 gap，需实测) |

### 3. Slack 一方集成不可类推到 Discord

- "Claude Code in Slack" 是 GitHub task delegator，**不是聊天界面**
- "Claude for Slack"（generic chat）走订阅但**不能挂自定义 MCP server**
- Anthropic 选择性建了 Slack 一方集成、未建 Discord 集成——产品决策，无技术 workaround

### 4. 既有方案已覆盖

Bot A + API 计费 + 便宜 preset（Gemini Flash Lite / Haiku）已能覆盖手机端查询需求（Discord 在手机端 UX 已习惯）。Bot B 这层是"复制 Bot A 一遍 + 加 MCP 协议开销 + 加 Anthropic API 账单条目"，零净收益。

## 真正能同时拿到"手机 UX + 订阅计费 + 自定义 MCP"的路径

**SSH + CLI claude**——

- 手机装 Termius / Blink Shell / a-Shell
- SSH 到 Mac
- 跑 `claude` 交互式 REPL
- `~/.claude/settings.json` 注册本机 stdio MCP server

四个变量同时勾上：手机能用 ✅、订阅计费 ✅、自定义 MCP ✅、零代码工程 ✅。

唯一代价：Discord UX 换成 SSH terminal。如果以后想做这个方向，**只需要保留 `obsidian_search.py` 和 `lifetracker_mcp_server.py` 这两个文件的代码骨架**（git history 里翻 `465aefb`），不需要 Bot B 的 Discord listener / agent loop / main entry。

## 元层教训
