# 14
接 #12。bot 在我内耗混沌时帮不上忙这个问题，之前试过让 AI 自己识别状态（在 system prompt 塞 protocol 段），实测没改进还浪费 token，已经注释掉了。

新思路是把"识别"和"响应"解耦：
- 单开一个觉察 channel（绕开"日和"这个角色，纯粹是收纳口），我可以往里扔"我发现自己 xxx"这种觉察。
- 加一个轻 agent 只做一件事：读觉察消息 → 从固定枚举里选一个状态标签 → 写进 user_state 表（带 TTL）。
- schema 直接复用 CLAUDE.md 里 PROTOCOLS 段的 4 个状态（深度专注 / 迈不出第一步 / 高耗宕机 / 时间感偏移），不需要重新设计。
- 日和的 _build_prompt 注入当前未过期的状态标签到 Block 4，她按 PROTOCOLS 已有规则降询问频率，自身代码几乎不用动。
- 觉察原文不进日和的视野（保持"扔进去不回头"的初衷），只走独立表给前端回看。
- 只在觉察 channel 触发打标 agent，不被动捕捉主频道（避免把"累"误判成"宕机"，主动声明的觉察是高信号）。

还没敲定：TTL 多长（猜 2 小时？）、agent 用什么模型（小模型够，状态分类比日期推理简单）、独立 channel 还是斜杠指令、要不要给觉察消息一个最小 reaction。

scope 警告：这跟 #12 一样会让人想做 Merlin 全貌，先做"日和别在我宕机时来烦我"这一个子集就好。等下次又混沌的时候记一下"这条觉察我希望系统怎么处理"，攒 2-3 次实例再升 spec 不晚。
