# 个人精力与状态调度引擎（Merlin System）架构与落地计划

本计划旨在将传统的“时间记录仪”升级为**RPG 风格的个人精力管理与状态调度系统**。系统采用前后端分离微服务架构：**日和（Hiyori）**负责前端的自然语言交互与无感记录，**梅林（Merlin）**负责后端的数值结算、状态预测与算法迭代。

---

## 阶段零 (Phase 0)：混沌采集与无监督发现期
**核心目标**：不预设任何特征参数（X）和目标标签（Y），利用大模型和聚类算法自动发现你独有的生理运行规律，提炼专属的 Buff/Debuff 字典。

### 1. 动态特征与状态提取（日和侧）
修改日和的 Prompt，在常规的时间打卡工具中新增两个非结构化 JSON 字段。当你随口吐槽时，日和在后台悄悄完成语义提取：
* **`inferred_factors` (潜在环境/行为因子)**：如 `["下雨天", "高碳水饮食", "轻度缺觉", "开启新项目"]`。
* **`inferred_states` (潜在状态素描)**：如 `["脑子转不动", "打字飞快", "电子反胃"]`。

### 2. 状态星系聚类（梅林侧）
* **算法应用**：自然语言嵌入（Word Embeddings） + **聚类算法（K-Means / HDBSCAN）**
* **执行方式**：积攒 1-2 周数据后，梅林扫描所有非结构化标签，将语义相近的状态“揉”成几个聚集的星系。
* **人工命名 (Human-in-the-Loop)**：你根据梅林的聚类报告，将这些星系命名为你专属的词缀。例如：将“打字快、忘记喝水”的星系命名为 `[Buff: 午夜心流]`，将“恶心、不想看屏幕”命名为 `[Debuff: 碳水昏迷]`。

---

## 阶段一 (Phase 1)：基础设施与特征工程固化
**核心目标**：根据阶段零的探索结果，拍板确立系统的底层数据库 Schema，将混沌数据转化为可供机器学习的结构化数据。

### 1. 确定特征输入矩阵 (X)
将高频且影响显著的因子固化为数据库字段。示例参数：
* **生理指标**：`sleep_hours` (睡眠时长), `sleep_debt_3d` (三日累计睡眠欠债), `is_period` (是否生理期)
* **行为指标**：`continuous_focus_hours` (当前连续无休时长), `days_since_last_chill` (距离上次深度放松的天数)
* **环境指标**：`weather_condition` (天气), `heavy_meal` (是否刚摄入高碳水)

### 2. 确定状态输出字典 (Y)
建立 `modifiers_dict` 表，固化阶段零提炼出的 Buff/Debuff（分类标签）：
* **增益 (Buff)**：`[心流]`, `[灵感爆发]`, `[多巴胺充盈]`
* **减益 (Debuff)**：`[脑雾]`, `[烦躁内耗]`, `[清零宕机]`

---

## 阶段二 (Phase 2)：梅林核心算法引擎建设
**核心目标**：引入四大成熟的数据科学算法，全面解析你的精力模型，提供预测、预警与归因功能。

### 1. 晨间面板预测（多标签分类 Multi-label Classification）
* **应用场景**：每天早上或准备开启新项目前，评估当天的状态风险。
* **技术栈**：`scikit-learn` (如随机森林 Random Forest)。
* **运作机制**：输入今天的初始 X（昨晚睡了多久、生理期等），模型同时预测触发多个 Buff/Debuff 的概率。
* **输出示例**：“梅林预测：今日开启新项目获得 `[Buff: 心流]` 概率 75%，但触发 `[Debuff: 脑雾]` 概率 60%。”

### 2. 生存倒计时警告（生存分析 Survival Analysis）
* **应用场景**：在你进入高强度专注（Focus）状态时触发，计算你还能撑多久。
* **技术栈**：`lifelines` (Cox 比例风险模型)。
* **运作机制**：将“清零宕机”作为目标事件，持续工作时间作为时间轴，身上的各种 Debuff 作为加速衰竭的风险乘数（Hazard Ratio）。
* **输出示例**：“当前风险系数 3.0，预计 45 分钟后触发绝对宕机，建议立刻保存进度并撤离。”

### 3. 被动技能配方挖掘（关联规则 Association Rule Learning）
* **应用场景**：每周的离线数据复盘，寻找隐藏的“连招”。
* **技术栈**：`mlxtend` (Apriori 算法)。
* **运作机制**：扫描历史记录，寻找置信度极高的条件组合。
* **输出示例**：“发现高频规则：连续两天 `sleep_hours < 6` + `heavy_meal = True` $\rightarrow$ 必然触发 `[Debuff: 碳水昏迷]`。”

### 4. 状态异常诊断大侦探（贝叶斯网络 Bayesian Networks）
* **应用场景**：当你感觉状态极差，却不知道为什么时，进行“归因分析”。
* **技术栈**：`pgmpy`。
* **运作机制**：构建包含生理、行为、状态的有向无环图（DAG）。当你挂载了某个 Debuff，梅林通过贝叶斯定理逆推最大概率的诱因。
* **输出示例**：“你当前极度烦躁，经逆向网络推演，60% 是因为缺乏社交，30% 是因为项目难度过高。”

## 阶段三 (Phase 3)：全链路集成与动态校准 (RLHF)
**核心目标**：将梅林的预测能力接入日和的交互逻辑中，并引入“人类反馈强化学习”机制，让模型越用越准。

### 1. 系统数据流转闭环
1.  **日和轮询**：日和准备主动找你聊天时，先调用梅林的 API。
2.  **获取面板**：梅林根据当前时间戳和你的 X 参数，结算你身上正挂着哪些 Buff/Debuff。
3.  **动态响应**：日和读取结算结果。若你带有 `[Debuff: 脑雾]`，她将放弃催促进度，改为递上一个极低阻力的小台阶（如：“换个脑子，把那个无关紧要的 UI 颜色改一下？”）。

### 2. `@Merlin` 上帝视角校准 (人工微调)
在通信平台（如 Discord）中设立专用的超级指令，允许你随时 Override（覆写）算法的判定：
* **情景**：“`@Merlin` 你的预测错了，这次熬夜让我直接清零宕机了，今天算力为 0。”
* **模型迭代**：梅林接收到人工 Ground Truth 标签，立刻将今日状态强刷为宕机，并在当晚的批处理任务中，将这条“异常斩杀”数据喂给生存分析模型，重新拟合你的崩溃临界点阈值。

# 个人状态与精力调度引擎 (Project Merlin & Hiyori v2.0)

本系统采用**主干+影子双轨制（Dual-Track Architecture）**，结合大模型（LLM）的非结构化提取能力与传统机器学习的严谨预测。系统不仅负责调度你的精力和日程，还能随季节、生理周期和心态变化实现**自我迭代与打补丁**。

## 1. 核心微服务与数据流

| 模块 | 角色定位 | 核心机制 |
| :--- | :--- | :--- |
| **日和 (Hiyori)** | 前端记录器 / 雷达 | **贪婪采集**：除了进行结构化对话，永远在后台默默提取你的非结构化特征（天气、饮食、情绪），丢入 JSON 桶。 |
| **梅林 (Merlin)** | 算法中枢 / 数值策划 | **无情过滤与结算**：跑统计算法、预测宕机倒计时、结算 Buff/Debuff。每月输出“版本更新报告”。 |
| **DB (数据库)** | 演化档案馆 | **绝不删除**：采用“软删除（Soft Drop）”和“冷宫（Icebox）”机制。废弃参数只屏蔽不删除，保留历史追溯能力。 |
| **UI 面板** | 玩家状态大屏 | **拥抱并发**：多泳道时间轴 (Multi-lane)、GitHub 连击热力图 (Heatmap)、精力气泡图。 |

---

## 2. 系统双轨运行机制 (Dual-Track)

整个系统随时保持两条轨道并行，确保既有稳定的主线，又有不断探索的支线：

* **主干执行轨 (Production Track)**：梅林每天基于已经“转正”的固定特征（X）和固定词缀库（Y）进行概率预测。日和根据这套确定的状态面板，对你进行调度和干预。
* **影子侦察轨 (Discovery Track)**：日和的底层 Prompt 永远保留一条指令，从对话中提取未经确认的隐性变量（如：喝了奶茶、下雨天）和新奇情绪，存入 `inferred_factors` 和 `inferred_states` 的 JSON 桶中。

## 3. 实施路线图 (Evolutionary Roadmap)

### Phase 0: 混沌雷达与聚类炼丹 (永驻后台进程)
**目标**：不预设前提，让大模型（LLM）结合无监督学习自动寻找你的隐性生理规律。

* **LLM 语义提取**：日和在对话中自动提取 `环境/行为标签` 和 `主观情绪标签`。
* **聚类分析 (Clustering)**：梅林定期对收集到的标签进行 K-Means / 文本向量嵌入聚类，找出高频的“状态星系”。
* **人工命名 (Human-in-the-Loop)**：你将这些星系命名为专属词缀（如 `[Buff: 白噪音结界]`、`[Debuff: 碳水昏迷]`），并正式加入主干数据库。

### Phase 1: 基础设施与特征工程固化
**目标**：建立支持演化的底层数据库，跑通数据管道。

* **建立双层 Schema**：
    * 主干特征列（如 `sleep_debt`, `continuous_focus`）。
    * 探索 JSON 桶（存放日和抓取的未验证特征）。
* **软删除与冷宫机制**：永远不在数据库执行 `DROP COLUMN`。认为无效的参数打入“冷宫”，日和继续静默记录，但梅林主干计算时跳过它，随时可以“复活”。

### Phase 2: 梅林核心算法引擎
**目标**：引入带“自适应魔法”的算法，提供预测、倒计时和自动特征筛选功能。

* **模块 A：L1 正则化特征筛选器 (Lasso Regression)**
    * **功能**：把所有猜测的参数都扔进模型，算法会自动把对预测没有用的参数权重压成 0。不需要人工判断参数废弃，模型会根据你的近况自己“挑选”重要参数。
* **模块 B：清晨结算面板 (多标签分类 Multi-label)**
    * **功能**：基于今日初始 X，预测各个 Buff/Debuff 触发概率，生成每日风险评估。
* **模块 C：生存倒计时 (生存分析 Survival Analysis - Cox 模型)**
    * **功能**：在高压任务中预测“距离彻底宕机/清零”的剩余时间。
* **模块 D：连招挖掘机 (关联规则 Association Rules)**
    * **功能**：找出高置信度的连锁反应（如：下雨 + 没喝咖啡 = 90% 脑雾）。

### Phase 3: 闭环调度与静默升级 (RLHF & Deployment)
**目标**：实现人机协同，并建立安全的模型升级机制。

* **`@Merlin` 人工覆写 (RLHF)**：通过指令强制修改状态（“算错了，我今天彻底清零了”）。梅林自动将此作为正样本加入训练集，调整你的“斩杀线”阈值。
* **影子模式升级 (Shadow Mode Deploy)**：
    * 当引入新参数训练出“梅林 v2.0”时，不直接替换老模型。
    * 让 v2.0 在后台“空跑”预测并记录日志。
    * 运行两周后，若 v2.0 预测准确率明显高于 v1.0，再进行丝滑切换，彻底避免模型震荡。

## 4. 每月“版本更新报告”机制 (Patch Notes)

每个月末，梅林会对比【主干轨】和【影子轨】的数据，给你发送一份极具游戏感的数据研报，由你来决定系统本月的演化方向：

1.  **发现新兴词缀**：“通过影子数据聚类，发现新状态星系，建议新增 `[Debuff: 周三过载症]`。”
2.  **揪出隐性杀手**：“在最近的宕机事件中，频繁提取到天气特征。建议将 `Weather` 正式转正为底层 X 变量。”
3.  **废弃失效规则**：“`[睡饱了]` 这一 Buff 的生效概率已降至 40%，L1 正则化已将其权重调低。建议引入‘睡眠深度’替代‘睡眠时长’。”
