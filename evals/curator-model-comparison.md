# Curator 模型固定批次对照评测

- 文档性质：可持续追加的 eval protocol + results ledger，不是 ADR
- 建立日期：2026-07-19
- 架构背景：[Memory v4 architecture design](../docs/modules/memory/plan/memory-v4-design.md)

## 背景

curator / compact 换模型是常态需求(额度、价格、新模型上市),需要一个
可重复的选型程序。两个前提使它成为可能:

- curator 的 dry-run 不推进 cursor,**同一批消息可以反复喂给不同 preset**;
- compact 有离线 preview 脚本,不写任何状态。

此前的随手测试(拿当时最新的一批消息试新模型)无法区分"这批消息难"
还是"这个模型差",结论不可比也不可积累。

## 评测协议

换 curator / compact 模型时,必须用**同一批固定输入**对现任主力模型做
对照评测,批大小固定 50(实测的可靠性上限)。判据固定三条,按序淘汰:

1. **思考阶段**:无思考的 lite 模型在 compact 中静默丢弃旧钩子、
   篡改时态(将来时→完成时),直接出局,不必往下测;
2. **JSON 纪律**:用 `--no-repair` 测原始合规率。修复轮能救 markdown
   fence 这类表层错误,救不了结构性混乱;
3. **事实保真**:proposal 的 summary 逐条对照原文。这是唯一必须靠人的
   环节——确定性校验能验证 quote 是原文连续子串,但抓不住"引用是真的、
   总结是歪的"这类畸变,而这恰恰是决定敢不敢开 auto_apply 的那一条。

失败样本连同通过样本一起留档(`data/curator_proposals/`),模型的
已知毛病(如 glm 的 fence 随机复发)记入对应项目管理 issue。本文只记录
可复现的准入方法和评测结果，不作为运行时 preset 的事实来源。

## 方法选择

- **拿不同批次随手测**:输入不受控,"模型差"和"批次难"混淆,
  否决——这正是本 ADR 要取代的做法;
- **只看校验通过率**:自动化程度最高,但对第 3 条判据是盲的,
  flash-lite 正是通过了校验、栽在事实保真上。

## 后果

正面:选型结论可复现、跨时间可比;新模型准入门槛明确,不再靠印象;
第 2 条判据顺带给出修复轮的真实收益数据。

代价:第 3 条判据是人工环节,每个候选模型约需一次完整批次的人肉对照;
固定批次用久了可能对其特征过拟合,更换固定批次时旧结论需要重测基线。

## 评测记录

### 2026-07-20:curator 主模型与 fallback 初选

对同一段 `conversation_messages.id=241..340` 做匿名回放。每个候选读取
相同 100 条消息,在隔离 SQLite 快照内按批次顺序 apply;生产 memory 和
cursor 均不修改。

第一轮比较 `deepseek-pro` 与 `glm` 的 20/50 两种批大小:

- `deepseek-pro / 50`:100 分,两批均原始合规,约 63 秒;
- `glm / 50`:95 分,内容质量通过,但一批需要 repair,约 289 秒;
- `deepseek-pro / 20`:83.85 分,出现批次边界造成的过度泛化与二次更新;
- `glm / 20`:第三批 repair 后仍产生非法 evidence id,只完成 2/5 批。

据此从 curator 候选中淘汰 `glm`;保留全局 preset 供非 curator 路径或
历史审计使用,不把"curator 淘汰"误写成"删除 preset"。

第二轮固定使用 50 条批次,比较 `deepseek-pro`、`kiro`、
`nepula-opus-4-7`:

- `kiro`:100 分,两批均原始合规,约 22 秒;
- `deepseek-pro`:96.6 分,两批均原始合规,约 77 秒;差异来自把两种相近的
  `interaction_style` 合并为一条,事实与证据本身无误;
- `nepula-opus-4-7`:首批需要 repair,第二批返回 Cloudflare 524;
  已完成输出还用 assistant-only 文本建立用户所在地,并把一次推进泛化为
  稳定工作模式,淘汰。

当前结论:`deepseek-pro` 继续作为 curator 主模型,`kiro` 作为 fallback
首选。原因不是忽略第二轮胜负,而是跨固定批次稳定性:`kiro` 此前在
`171..220` 的重复回放中曾漏掉有效偏好,而 `deepseek-pro` 多次稳定提取;
`kiro` 在本轮则证明了足够的质量、JSON 纪律和更低延迟。正式打开
auto-apply 前,仍需再换至少两个固定区间复测这组主备组合。

### 2026-07-20:下一段滚动回放 `341..440`

继续只比较 `deepseek-pro` 与 `kiro`,固定 50 条批次。为保证这是真正的
连续 curator 回放,两个候选都从上一轮 reviewed winner 的最终 active
memory 集合开始:在隔离 SQLite 快照中携带 `241..340` 新确认的两条
`interaction_style`,再分别处理 `341..440`;不修改生产 cursor/memory。

两个模型均输出 `operations=[]`,人工评分均为 100 分。空操作是正确结果:

- `id=350` 对个人项目的热情已被现有 Memory 6 覆盖,没有必要为措辞变化更新;
- 作业和 quiz 完成属于时间线事件,不能因此 archive 课程状态;
- 疲惫、头疼、上课犯困和看日出是短期状态;
- "趁我睡觉整理记忆"是一次性指令,不是长期互动偏好。

自动指标同样全部通过:`kiro` 两批约 18 秒,`deepseek-pro` 两批约 39 秒,
均无需 repair。该批验证了两者的去重和克制能力,但因为没有新的应收录事实,
没有提供 recall 差异;累计结论保持 `deepseek-pro` 主、`kiro` fallback。

### 2026-07-21:下一段滚动回放 `441..540`

> 本段至 `741..840` 的内容判断为助理初评,用于准备审查材料,不视为用户的
> 最终人工评分;模型自动指标仍为原始运行结果。

继续固定 50 条批次,并从上一轮 reviewed winner(`kiro`)在 `341..440`
结束时的 active memory 集合接续。生产 cursor 和 canonical memory 仍未修改。

- `kiro`:100 分,两批均原始合规,约 18 秒;正确输出空操作;
- `deepseek-pro`:两批均原始合规,约 71 秒,但唯一 create 存在事实错误,
  按评测规则淘汰。

本批中 `id=477` 说用户有意评估 ADHD、嫌流程繁琐而暂未推进,但同批更晚的
`id=528` 已明确改为次日就诊且已经下定决心。`deepseek-pro` 只引用前一条,
将其总结成仍然有效的 `open_loop`;而评测发生于一个月后,预约已经过去且没有
后续结果,因此既不符合本批最新证据,也不符合 `open_loop` 的当前有效性要求。
`kiro` 正确避免了这条过期记忆,也没有误收已完成 quiz、workshop、午睡、
音乐会、普通 deadline 或已过期 Medibank offer。

累计 `241..540` 三个连续区间后,暂定顺序调整为 `kiro` 主模型、
`deepseek-pro` fallback:`kiro` 连续三段均为 100 分且延迟更低;
`deepseek-pro` 分别为 96.6、100、事实错误淘汰。这个顺序仍未冻结——
`kiro` 在更早的 `171..220` 重复回放中曾漏掉有效偏好,所以继续人工滚动评测;
在主备、批大小和停止条件正式确认前,生产 auto-apply 保持关闭。

### 2026-07-21:下一段滚动回放 `541..640`

继续从上一轮 `kiro` 的 reviewed 状态接续,固定 50 条批次:

- `kiro`:100 分,两批均原始合规,约 14 秒;正确输出空操作;
- `deepseek-pro`:两批均原始合规,约 49 秒,但唯一 create 存在事实错误,
  再次按规则淘汰。

`deepseek-pro` 将一个月前的 ADHD 流程写成当前仍在等待两个渠道回电。
原文能证明用户当时已获得 GP referral,但没有更晚证据证明该等待状态在评测时
仍然成立;并且 `id=584` 只明确说机构需要回电,没有证明私人医生渠道也会回电。
这既违反 current_state 的近期证据要求,也对来源作了小幅扩写。`kiro` 正确避免
入库,且没有重复收录已有的个人项目偏好或误收睡眠、hyperfocus、课程、活动和
工具反馈等一次性/短期内容。

至此 `deepseek-pro` 连续两个区间都暴露了同一种时效问题:抓住流程早期状态,
但未能判断它在评测时是否仍为当前事实。`kiro` 暂定 primary 的依据进一步增强,
但仍需在包含明确、长期有效新信息的区间验证 recall,不能只凭连续空操作冻结。

### 2026-07-21:下一段滚动回放 `641..740`

两个模型均输出 `operations=[]`,人工评分均为 100 分;两批原始 JSON 全部
合规且无需 repair。`kiro` 约 11 秒,`deepseek-pro` 约 32 秒。

空操作是正确结果:ADHD 等待、电话问诊和学校 intake 都是一个月前且结果未知
的流程事件;当时想投诉且不再去某诊所缺少可独立识别的对象;睡眠、饮食、
课程和活动是短期事件;写记忆系统也已被现有个人项目偏好覆盖。本段继续支持
两者的 restraint 与 `kiro` 的延迟优势,但仍没有有效的新长期事实可比较 recall。

### 2026-07-21:下一段滚动回放 `741..840`

两个模型再次正确输出空操作,人工评分均为 100 分,原始 JSON 全部合规且无需
repair。`kiro` 约 11 秒,`deepseek-pro` 约 48 秒。

本段虽出现 XT50,但只确认已交定金并计划下周取货;评测时取货日期已过去且没有
结果,不能直接写成当前持有,也不能从一次购买推断稳定摄影偏好。Medibank 计划
同样已过期;做蛋糕、睡眠、Costco 和课程提醒都是短期事件。本段仍只验证了
restraint,下一段应重点检查是否出现实际取货或其他可独立成立的新长期事实。

### 2026-07-21:用户盲审 `841..940`

继续从上一轮 `kiro` 状态接续,固定 50 条批次。此次将完整 transcript、baseline、
匿名 operations 与 final active memories 整理到
`data/curator-blind-review-841-940.md`,由用户直接审查,不加入助理评语。

用户选择 Candidate B。揭盲结果:

- Candidate B = `kiro`:两批完成,无 repair,约 28 秒;
- Candidate A = `deepseek-pro`:两批完成,一批需要 repair,约 66 秒。

`kiro` 提取了固定思绪整理习惯、夜间集中精力偏好,并 supersede 已失效的
签证/OSHC 计划;`deepseek-pro` 只 update 签证/OSHC 计划。该批终于包含明确的
新长期信息,用户选择直接验证了 `kiro` 的 recall,同时 `kiro` 的原始 JSON 纪律
和延迟仍更好。此处只记录用户的整体选择,不伪造未提供的细分评分。
